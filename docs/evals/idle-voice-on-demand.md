# On-demand voice — 2026-10-28

The kiosk no longer starts or maintains a prepared native voice thread/call at API startup, during idle presence detection, or after guest teardown. Startup still warms the local Fusion worker; requesting voice options may start the Codex app-server and list voices, but does not create a customer thread or voice call. A detected customer or manual start creates a fresh customer session and native thread. Native transport owns a 30-second attempt timeout, with a 35-second host deadline for completion/cleanup, and retries while the guest remains active; 8–12 second readiness is not guaranteed. The former 20-second host deadline was removed because it cancelled the transport before its own handshake deadline.

Greeting audio is sent as a generation-bound announcement only after actual browser microphone packets, confirmed Fusion session initialization, and native voice readiness, once per guest. Microphone freshness and Fusion/Visual readiness are checked again after native negotiation. No greeting is sent if the guest leaves or connection fails before readiness; reconnects do not replay it. PCM and native transcript/output are not forwarded before the greeting. Existing locally recorded goodbye behavior is preserved. See [device camera and AV readiness](device-camera-av-readiness.md) for current evidence and physical-device limitations.

Verification in isolated fixtures: 36 unit tests (`output/idle-voice-unit-final.txt`), 7 browser cases (`output/idle-voice-browser-final.txt`), 21 frontend tests (`output/idle-voice-frontend.txt`), frontend build/lint and Python lint. Includes blocked and failed native negotiation, selected voice, camera source, guest departure, no idle preparation, retry without repeated greeting, and pre-ready audio gating. No actual customer or merchant action was performed. Quota meter changes and physical microphone/camera latency have not been measured.

The full Python suite passed: **293 tests in 117.16 seconds** (`output/idle-voice-pytest-final.txt`). The preceding full run exposed a transcript fixture that assumed speech before greeting; it was updated to initialize a ready Fusion/native session before testing transcript delivery.
